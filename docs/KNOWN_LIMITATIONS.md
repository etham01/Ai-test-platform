## 2. 环境导致无法真实验证的部分

### 2.1 Docker 隔离执行

- **未实现/未验证**：DockerRunner、`docker/runner.Dockerfile`、Compose 执行 profile；API 对 `mode=docker` 返回 409。
- 原因：本机无 Docker，WSL 未安装；无法构建/运行容器、无法验证非 root/只读/资源限制/网络策略。
- 交付方式：保留 `docker-compose.yml`（MySQL/Redis 基础设施）与设计说明；Docker 执行器未实现，文档标注。
- 影响：本地执行模式只能提供有限隔离，**不是安全沙箱**；不得用于运行不受信任脚本或访问不受信任站点。

### 2.2 真实 LLM 供应商

- **未验证**：真实 OpenAI 兼容服务的鉴权、限流、超时、模型差异、JSON 稳定性。
- 原因：无 API Key，且不应伪造凭据。
- 交付方式：
  - `OpenAICompatibleClient` 完整实现；
  - `MockLLMProvider` 用于演示/测试；
  - 用 `httpx.MockTransport` 验证正常/429/超时/无效 JSON；
  - UI 显示 Mock/真实徽标；
  - `.env.example` 与项目设置提供配置入口。
- 用户后续提供 Key 后，需重新跑 `llm-config/test`、生成用例/脚本/失败分析，并记录结果。

### 2.3 精确 MySQL 8.0 / Redis 7

- 本地 MySQL 为 9.4.0；Compose 提供 `mysql:8.0`，但当前无法运行验证。
- 本地 Redis 为便携版 8.10.3（redis-windows 第三方构建）；Compose 提供 `redis:7`，未验证精确 7.x 组合。
- 影响：SQL/JSON/Celery 基础功能应在两者兼容，但未在精确版本组合上做全量回归。
- 处理：使用标准 SQLAlchemy/Alembic；不依赖 9.x 特有语法；文档记录版本差异。

### 2.4 Playwright 浏览器

- 未安装；Chromium 约 178 MB，网络可能慢。
- 回退：使用系统 Chrome（`PLAYWRIGHT_CHANNEL=chrome`）；版本与 Playwright 预期可能不同。
- 影响：页面采集/执行前必须确认浏览器可启动；否则任务失败并给出明确错误。

### 2.5 第三方真实站点

- 未获得任何站点授权；不会扫描公网/第三方站点。
- 仅使用本地 `demo_site`（127.0.0.1:8001）验证。
- 影响：真实站点的登录、验证码、复杂 SPA、反爬、跨域 Cookie 等未验证。

## 3. 功能范围限制

### 3.1 单用户与认证

- MVP 为单用户（默认 `demo`），无登录页、无 OAuth、无角色权限。
- 通过 `owner_id + project_id` 做数据隔离，但默认无认证；仅适合本地。
- 可选 `SMARTTEST_API_TOKEN` 只是轻量门槛，不是完整身份系统。
- 公网部署必须补认证/HTTPS/限流/审计。

### 3.2 多页面探索

- 默认 `max_pages=8`、`max_depth=2`；不是全站爬虫。
- 只跟随同源链接；默认不跟随外域（即使重定向也复检）。
- **不自动提交表单**；登录/下单/删除等流程只记录 form action，由生成的测试脚本执行。
- 不处理验证码、登录绕过、访问控制绕过。
- 不保证覆盖 SPA 动态路由/懒加载/WebSocket 更新；以 `domcontentloaded` + 短等待为主。
- 不做 robots.txt 合规爬取策略（仅同源/限额/延时）；生产需补充。
- 页面元素最多约 80 条/页，文本/DOM 截断；复杂页面可能丢失低优先级元素。
- 页面关系是“观察到的链接/跳转/表单动作”，不是完整业务依赖图；LLM 推断边单独标记。

### 3.3 登录态

- **未实现（P1）**：Playwright `storage_state` 上传/加密；当前只采集公开页面，登录流程由生成脚本执行；不提供验证码/自动登录绕过。
- `storage_state` 含 Cookie，属于敏感数据；需加密存储、最小权限、及时清理。
- demo 站点登录由生成脚本执行，不依赖预置会话。

### 3.4 业务流程与用例

- LLM/Mock 生成的流程是**候选**，不是站点真实规则；`model_inference` 必须人工确认。
- 用例结构校验只保证字段/引用合法，不保证业务正确性。
- “覆盖率”仅指自定义维度（页面/流程/需求）覆盖，**不是代码覆盖率**。
- 用例去重是启发式（标题/页面/步骤），可能漏判/误判。
- 不自动把模型推断写成确定业务规则。

### 3.5 脚本生成

- 生成脚本是“草稿”，即使通过 AST 校验也可能定位器不稳、等待不足、断言错误。
- 语义定位优先（role/label/placeholder/text），复杂组件可能仍需 CSS/人工修改。
- 不保证脚本可直接用于生产站点；需人工 review、调试、参数化。
- 每个用例默认一个脚本文件；跨用例共享 fixture/模块组织有限。
- 脚本编辑会新增版本，不会原地覆盖旧版本；旧版本保留用于审计。

### 3.6 执行与报告

- 本地模式：无 cgroup/Job Object 硬资源限制；超时/进程树终止是主要兜底。
- 本地模式不是沙箱；AST 检查可被绕过；只允许受控 demo。
- 执行只支持 Chromium/headless 为第一版；其他浏览器未验证。
- 报告使用 pytest-html；样式/交互有限；报告可能包含页面文本，存在 XSS 风险（下载/CSP 缓解）。
- 失败截图依赖 `page` fixture；脚本自行创建浏览器/关闭页面时可能无截图。
- 失败分析是模型推测，必须与“观察到的错误”区分；不自动修复/重跑。
- 并发执行在 Windows solo worker 下实际串行；多任务会排队。
- 取消在 LLM 请求中间可能等待到超时；扫描在执行当前页面导航时也可能延迟。

### 3.7 任务与持久化

- 任务状态以 MySQL 为准；Redis 仅队列/短期协调。
- 单 worker（Windows solo）时，长任务会阻塞后续任务；这是演示可接受、生产不可接受。
- 任务日志每任务 ≤500 条；详细日志在文件；历史清理未自动化。
- 文件存储为本地磁盘，无对象存储/多机共享；备份/迁移需手动。
- 项目/用例/脚本软删除；硬删除默认关闭；执行历史默认保留。

### 3.8 前端

- 以桌面管理端为主，未做移动端适配。
- 页面关系图为轻量 SVG/列表，不是专业图分析工具。
- 任务进度为轮询（1.5–2s），未用 SSE/WebSocket。
- 代码编辑为 textarea + 预览，不是 Monaco/IDE；大脚本体验有限。
- 中英文混排；未做完整 i18n。
- 基础组件、Table、Select、Checkbox、Alert、Dialog、Sonner 已通过官方 shadcn-vue CLI（reka-nova）接入；views 层不再使用原生 table/select/checkbox/input/textarea。

## 4. 安全限制（务必阅读）

1. **本地执行模式不是安全边界**：不要用它运行来源不明/未审查的脚本，不要对不受信任站点开放。
2. **SSRF 防护是分层的应用层控制**：DNS rebinding 存在残余窗口；脚本/浏览器行为可能绕过部分检查；Docker 出口代理未实现。
3. **AST 不是沙箱**：黑名单/白名单只能降低风险；真正的隔离需要容器 + 最小权限 + 网络限制。
4. **单用户无正式认证**：默认仅 127.0.0.1；公网暴露前必须补认证。
5. **报告/日志可能含不可信页面文本**：已做转义/下载/CSP 设计，但未做完整 HTML sanitizer。
6. **密钥安全依赖部署**：`.env`/`SMARTTEST_SECRET_KEY` 管理不当会泄露；开发密钥文件不得提交。
7. **便携 Redis 8.10.3 为第三方 Windows 构建**：仅开发、localhost、可设密码；生产用 Redis 7 容器并加网络隔离。
8. **Docker 未验证**：不要宣称“已实现容器隔离”；当前只有代码路径与配置。

## 5. Mock 与真实 LLM 的区分

| 维度 | MockLLMProvider | 真实 OpenAI 兼容 |
| --- | --- | --- |
| 用途 | 演示/自动化测试/无 Key 环境 | 真实生成 |
| 输出 | 基于页面/用例的确定性模板 | 模型生成，可能不稳定 |
| DB 标记 | `is_mock=true`、`generation_source=mock` | `is_mock=false`、`generation_source=llm` |
| UI | 黄色“Mock 演示模式”横幅/徽标 | 绿色“真实模型”徽标 |
| 测试连接 | 返回成功 + 明确 Mock 文案 | 实际请求；失败明确报错 |
| 能力 | 覆盖 demo 流程，不追求通用 | 依赖模型/上下文/网络 |
| 诚实性 | 不冒充真实模型效果 | 未配置 Key 时不假装成功 |

**当前仓库默认演示使用 Mock；真实客户端已实现但未用真实 Key 验证。**

## 8. 交付时如何表述

最终总结必须按以下格式，不得混淆：

1. **已完成并实际验证**（附命令/结果/日期）：
   - 例：项目 CRUD、MySQL 迁移、Mock 生成、demo 站点采集、AST 拒绝、通过/失败执行、报告下载。
2. **已实现但当前环境未验证**：
   - 例：DockerRunner（未实现）、Compose 全栈、真实 LLM 供应商调用、Redis 7/MySQL 8.0 精确组合。
3. **尚未实现**：
   - 例：Docker 出口代理、多用户认证、SPA 深度采集、报告 sanitizer。
4. **需要用户提供**：
   - 例：真实 LLM Key、Docker 环境、外部站点授权、MySQL 3306 凭据。

> 任何“应该可以”“理论上支持”都不算验证。以实际命令输出为准。
